# Simulation-Based Expert Action Collector (2026-03-02)

## 背景
本次新增了一个“仿真驱动”的 expert_action 采集方案，用短时仿真替代 LLM 决策，并保持原有 `traffic_prompt_series_*.jsonl` 的输出格式不变。

## 思路概述
1. 继承并复用 `LLM_Inference_VLLM` 的环境初始化与数据记录逻辑，但禁用 LLM 初始化。
2. 在每个决策步，对每个路口枚举 4 个相位候选，基于同一快照进行短时仿真。
3. 统计候选相位在仿真窗口内的“平均等待时间”，选择最小者作为 `expert_action`。
4. 将选择结果写入 `traffic_prompt_series_*.jsonl`，并在每组最后一行额外记录 `candidate_action_waits`、`expert_action_margin`、`base_action` 等 richer supervision 字段。

## 关键实现
- 新类：`utils/sim_expert_collector.py` 中的 `SimExpertCollector`  
  - `initialize_llm()` 置空，避免加载模型。  
  - `_phase_state_snapshot/_phase_state_restore` 保存并恢复相位相关状态。  
  - `_apply_action_no_log` 用“静默”方式更新信号灯状态，避免写日志和污染交通统计。  
  - `_simulate_candidate` 基于快照做短时仿真，计算平均等待时间。  
  - `test()` 中替换 LLM 推理为“枚举候选 + 选择最优”流程。

- 新脚本：`run_sim_expert_action.py`  
  - 结构与 `run_open_LLM_with_vllm.py` 一致。  
  - 可选使用 LLM 生成 `clip_caption`，也可以退回规则 caption。  
  - 新增可选参数 `--sim_wait_speed` 与 `--sim_horizon_s`。  

## 评价指标
等待时间定义：在仿真窗口内，对目标路口入口车道上的车辆，当 `speed < SIM_WAIT_SPEED` 时累计 1 秒等待；最终以“总等待秒数 / 唯一等待车辆数”作为平均等待时间。

## 运行示例
```bash
python run_sim_expert_action.py \
  --dataset jinan \
  --traffic_file anon_3_4_jinan_real.json \
  --llm_model gemma-3-27B \
  --llm_path /home/data/model/gemma-3-27B/ \
  --clip_caption_mode prompt_llm \
  --sim_horizon_s 30 \
  --sim_wait_speed 1.0 \
  --ts_image_seq_len 16
```

## 当前推荐全流程命令

### 1. 清洗训练集

```bash
python utils/clean_align_jsonl.py \
  --inputs \
    data/recorded/anon_3_4_jinan_real_2500.json_03_03_07_16_31/traffic_prompt_series_2s.jsonl \
    data/recorded/anon_3_4_jinan_real.json_03_03_10_54_17/traffic_prompt_series_2s.jsonl \
  --output data/recorded/align_train.cleaned.jsonl \
  --seq_len 16 \
  --min_action_margin 0.5 \
  --dedup_similar_captions
```

### 2. 第一阶段 Alignment

```bash
torchrun --nproc_per_node=4 train_align.py \
  --data_path data/recorded/align_train.cleaned.jsonl \
  --model_path /home/data/model/qwen-vl-8B/ \
  --batch_size 16 \
  --grad_accum_steps 4 \
  --bf16 \
  --lr 2e-4 \
  --temperature 0.07 \
  --prefix_tokens 16 \
  --prefix_mode prefix
```

### 3. 第二阶段 BC

```bash
torchrun --nproc_per_node=4 projection_train/train_projection_bc.py \
  --data_path data/recorded/align_train.cleaned.jsonl \
  --llm_path /home/data/model/qwen-vl-8B/ \
  --align_ckpt records/align/align_epoch_60.pt \
  --output_dir records/projection_bc \
  --batch_size 1 \
  --seq_len 16 \
  --epochs 10 \
  --max_length 128 \
  --prompt_mode image_only_short \
  --lr 1e-4 \
  --grad_accum_steps 4 \
  --bf16 \
  --image_size 224 \
  --prefix_tokens 16 \
  --prefix_mode prefix \
  --target_mode mixed \
  --soft_target_alpha 0.5 \
  --soft_label_temperature 2.0 \
  --min_action_margin 0.5
```

## 约束与注意
- 当前仅支持 4 相位（若启用 8 相位需同步更新 prompt 与 action 映射）。
- 评估时对每个路口独立优化，其他路口固定当前相位。
