# PhaseVLM Stage 3 Research Idea Report

**Direction**: A genuinely innovative Stage 3 beyond random few-shot SimExpert relabeling for a frozen Qwen3-VL traffic signal policy
**Generated**: 2026-08-11
**Ideas evaluated**: 16 brainstormed -> 11 retained and ranked -> 3 proposed as first pilots -> 0 launched
**Compute constraint**: At most 2 x RTX 5090; simulator work should remain bounded and auditable

## Scope and Evidence Status

This report treats `idea-stage/codex_brainstorm_bundle.md` as the supplied landscape. It also checks the current repository implementation, especially `scripts/relabel_simexpert.py`, `projection_train/train_projection_bc.py`, `projection_train/prefix_action_policy.py`, and `projection_train/topology_adapter.py`. No external novelty search or pilot experiment was run in this brainstorm-only task. Consequently, literature positioning inherited from the bundle should be rechecked before paper claims are made.

The current implementation is already beyond a hard-label-only sketch. It can store four-action counterfactual metrics, mask Pareto-infeasible actions, train hard or soft targets, add pairwise cost ranking, and condition the vision representation on an intersection MLP. A useful Stage 3 contribution therefore cannot be merely "use all action costs," "add a GNN," or "sweep the queue/wait weight."

## Landscape Synthesis

PhaseVLM has an unusually useful research instrument: exact state snapshots can be replayed under each candidate phase while the expensive VLM remains frozen and only compact TS2I/prefix modules are adapted. The strongest Stage 3 should exploit the simulator as more than a label generator. It should use counterfactuals to test whether the expert itself is reliable, decide which states deserve simulation, or expose structure that cannot be learned from hard winners.

Three assumptions are currently untested. First, a phase that wins after one fixed 30-second rollout may not win at a longer horizon or under a slightly different future arrival process. Second, evaluating one intersection while all neighbors retain their saved phases assumes local counterfactual advantages compose across the network. Third, a one-shot adaptation batch assumes the adapted policy will continue to visit the same state distribution. Any of these assumptions can invalidate sophisticated preference losses while leaving offline validation accuracy apparently healthy.

The topology path has a similarly sharp opportunity. The current topology encoder is a learned lookup over normalized grid position, four neighbor-existence bits, and network size. It does not encode movement connectivity, lane capacity, phase compatibility, upstream congestion, or permutation equivariance. A graph-conditioned prefix is promising only if it is tested against intersection-ID permutations and held-out structures, so that memorization cannot masquerade as topology transfer.

Finally, the observed Queue-Wait trade-off suggests that Stage 3 should learn a family of feasible policies or enforce explicit constraints, rather than search for one universal scalarization. The four-action counterfactual table is small enough to support listwise, robust, and Pareto objectives without unstable online RL.

## Recommended Ideas

### 1. Multi-Horizon Preference Stability and Temporal-Robust Distillation

- **One-sentence summary**: Evaluate every candidate phase at several rollout horizons, quantify action-rank reversals, and distill a horizon-robust preference only if the fixed-horizon expert proves unstable.
- **Core hypothesis**: Short rollouts favor immediate queue discharge while longer rollouts expose downstream spillback and starvation, so a nontrivial fraction of 30-second winners will have high 90- or 120-second regret.
- **Minimum viable experiment**: Reuse 32 complete network snapshots, stratified by congestion, from each transfer direction. Evaluate all four actions at `H in {15, 30, 60, 120}`. Report best-action flip rate, Kendall rank correlation, and normalized regret of the `H=30` winner at longer horizons. Only if flips are material, train one horizon-conditioned or worst-horizon soft target and compare it with current 30-second soft distillation on a held-out flow.
- **Bidirectional value**: High reversal rates invalidate the current expert definition and motivate a temporal-robust method; low rates justify cheap 30-second labels and remove a major reviewer concern.
- **Contribution type**: Diagnostic first, then empirical finding or new method.
- **Risk level**: LOW. The audit produces a useful answer even if no new loss is needed.
- **Estimated effort**: 3-5 days; roughly 4x the simulator cost of the same 32-snapshot relabeling run and 0-1 GPU-hour for optional distillation.

### 2. Interaction-Aware Joint Counterfactual Expert

- **One-sentence summary**: Measure and model non-additive effects between adjacent intersections instead of assuming that independently best local phases form a good network action.
- **Core hypothesis**: Under directional waves and spillback, the cost of phases at adjacent intersections contains strong interaction terms, making unilateral SimExpert labels mutually inconsistent when deployed simultaneously.
- **Minimum viable experiment**: Select 24 congested snapshots and, for one high-pressure adjacent pair per snapshot, evaluate all `4 x 4 = 16` joint phase combinations while holding the rest of the network fixed. Compare the exhaustive pair optimum with the combination of two unilateral winners and compute the interaction residual `Delta C_ij(a_i,a_j) - Delta C_i(a_i) - Delta C_j(a_j)`. If interactions are large, fit a low-rank edge-factor cost model and choose coordinated phases with one round of max-sum message passing.
- **Bidirectional value**: Large interactions establish a new failure mode and motivate coordination-aware Stage 3; small interactions validate scalable independent labeling and support the current design with direct evidence.
- **Contribution type**: Diagnostic plus new method.
- **Risk level**: MEDIUM. The audit is straightforward, but a full network-level coordinator is a larger extension.
- **Estimated effort**: 1-2 weeks; no large-model training for the audit, then 1-3 GPU-hours for an edge-factor critic and prefix fine-tuning.

### 3. Regret-Aware Active SimExpert Querying

- **One-sentence summary**: Query states according to estimated policy regret and uncertainty in action cost, rather than policy entropy or random sampling alone.
- **Core hypothesis**: Policy entropy wastes expensive labels on harmless ambiguity, whereas `expected cost of deployed action - expected best cost`, multiplied by epistemic uncertainty and batch diversity, targets decisions that are both uncertain and consequential.
- **Minimum viable experiment**: From a fixed pool of at most 120 complete decision snapshots, query 8 random snapshots to train a bootstrap ensemble of lightweight four-action cost heads on frozen PhaseVLM embeddings. Acquire three batches of 8 snapshots using predicted regret plus diversity, for a total `K=32`. Compare against random, policy entropy, and embedding OOD selection using exactly the same queried pool, training steps, and source checkpoint. Primary endpoints are held-out counterfactual regret and paired online AWT/AQL, not validation accuracy.
- **Bidirectional value**: A gain supports a publishable budgeted-oracle method; a null result shows that label diversity or expert noise, rather than acquisition, is the limiting factor.
- **Contribution type**: New method plus label-efficiency empirical finding.
- **Risk level**: MEDIUM. Acquisition can fail early when only eight labels seed the cost ensemble.
- **Estimated effort**: 1-2 weeks; about the simulator cost of 32 network snapshots per method and 2-6 total GPU-hours for a small pilot matrix.

### 4. Budget-Neutral Counterfactual DAgger

- **One-sentence summary**: Spend the same SimExpert budget over several collect-label-update rounds so each round labels states visited by the newly adapted policy.
- **Core hypothesis**: One-shot target adaptation underperforms because the updated policy visits states absent from its original collection rollout, and iterative on-policy counterfactual labeling will reduce this covariate shift without increasing the label budget.
- **Minimum viable experiment**: Compare one-shot `32 x 1` adaptation with `8 x 4` rounds. Both arms use 32 complete network snapshots, the same total optimizer steps, identical held-out validation/test flows, and the same source checkpoint. After each 8-snapshot round, update only prefix/TS2I modules, recollect with the new policy, and keep the cumulative dataset. Track state-embedding drift and per-round counterfactual regret.
- **Bidirectional value**: A gain demonstrates that label timing matters more than label count; no gain validates the simpler one-shot protocol and rules out covariate shift as the main bottleneck.
- **Contribution type**: Empirical finding and adaptation method.
- **Risk level**: LOW. The current evaluator hook and adaptation pipeline already provide most components.
- **Estimated effort**: 5-8 days; 2-4 GPU-hours for the pilot plus the same 32-snapshot SimExpert budget in both arms.

### 5. Directional Symmetry Audit and Equivariant Prefixing

- **One-sentence summary**: Rotate or reflect movement histories and topology while consistently permuting action labels, then enforce prediction equivariance if PhaseVLM fails this traffic-semantic invariance test.
- **Core hypothesis**: TS2I layout, movement ordering, and learned intersection IDs create avoidable orientation shortcuts that hurt transfer more than raw grid-size mismatch.
- **Minimum viable experiment**: Apply valid local direction permutations, especially 90-degree rotation where `ETWT <-> NTST` and `ELWL <-> NLSL`, to held-out sequences and corresponding topology/action metadata. Measure equivariance KL and top-1 consistency without retraining. If the gap is large, add a consistency loss between original and transformed examples and repeat Jinan-to-Hangzhou and Hangzhou-to-Jinan evaluation.
- **Bidirectional value**: Failure reveals a precise architecture bug with a cheap correction; success is strong evidence that learned prefixes represent traffic semantics rather than naming/layout artifacts.
- **Contribution type**: Diagnostic plus representation method.
- **Risk level**: LOW. The transformation test is cheap and falsifiable.
- **Estimated effort**: 3-6 days; under 2 GPU-hours including one consistency-training ablation.

### 6. Stochastic-Future Robust SimExpert

- **One-sentence summary**: Define action preferences over a distribution of plausible near-future arrivals instead of one deterministic continuation of each snapshot.
- **Core hypothesis**: Candidate rankings with small margins are unstable to future vehicle arrivals and lane-change randomness, so deterministic SimExpert overstates label certainty precisely where hard or low-temperature targets are most harmful.
- **Minimum viable experiment**: Extend snapshot replay to preserve current vehicles while varying only future entrants or seeded lane-change trajectories. For 20 snapshots, evaluate four actions under 8 plausible futures and measure winner probability, cost variance, and deterministic-winner CVaR regret. Compare deterministic labels with probability-of-optimality targets and `CVaR_0.8` targets on one transfer direction.
- **Bidirectional value**: Instability motivates risk-aware labels and explains margin failures; stability validates deterministic replay and avoids unnecessary robust optimization.
- **Contribution type**: Diagnostic and new robust-preference method.
- **Risk level**: MEDIUM. CityFlow future-arrival perturbation must be implemented without corrupting the saved state contract.
- **Estimated effort**: 1-2 weeks; simulator-heavy, with 1-2 GPU-hours for the target comparison.

### 7. Reference-Anchored Listwise Counterfactual Preference Optimization

- **One-sentence summary**: Optimize relative action log-probability ratios against the frozen source policy using all four SimExpert costs and their margins, rather than treating preference optimization as another hard winner loss.
- **Core hypothesis**: In few-shot adaptation, a source-policy reference prevents destructive probability shifts while listwise margin targets preserve the information discarded by hard BC and unweighted pairwise hinge ranking.
- **Minimum viable experiment**: On one fixed full-SimExpert dataset, compare hard BC, current soft CE, current pairwise hinge, pairwise DPO, and a listwise reference-ratio objective. Construct pair targets from raw cost gaps, mask constraint-violating actions, and keep architecture, samples, optimizer steps, checkpoint selection, and seeds identical. Evaluate counterfactual regret, KL from the source policy, and paired online metrics.
- **Bidirectional value**: Improvement establishes the counterfactual preference-optimization claim; a clean null result strengthens the existing finding that label quality dominates loss design and prevents an overclaimed DPO story.
- **Contribution type**: New method or decisive negative empirical finding.
- **Risk level**: LOW-MEDIUM. The objective is simple, but gains over well-calibrated soft targets may be small.
- **Estimated effort**: 4-7 days; 3-6 GPU-hours for a focused multi-seed loss comparison using already collected labels.

### 8. Selective Test-Time Counterfactual Verification

- **One-sentence summary**: Add a calibrated risk gate that invokes SimExpert only when the deployed action is likely to incur high regret or violate wait/spillback constraints.
- **Core hypothesis**: A small fraction of rare, shifted, or high-congestion states accounts for most transfer regret, so verifying only the riskiest 1-10% of decisions can recover most benefits of always-on simulation.
- **Minimum viable experiment**: Train a small risk head from existing candidate metrics to predict deployed-action regret and violation probability. On a held-out shifted flow, evaluate query rates `{0, 1, 5, 10, 100}%`; queried decisions take SimExpert's feasible winner, while others use PhaseVLM. Plot ATT/AQL/AWT/spillback against simulator seconds and wall-clock decision latency. Calibrate thresholds only on a separate flow.
- **Bidirectional value**: A steep performance-cost curve yields a practical hybrid controller; a flat curve shows that errors are diffuse and online simulator guidance is not deployable under a small budget.
- **Contribution type**: New method and deployment diagnostic.
- **Risk level**: MEDIUM. Exact SimExpert latency may be incompatible with real-time control, making a surrogate necessary.
- **Estimated effort**: 2-3 weeks; 2-4 GPU-hours plus potentially substantial but explicitly budgeted simulator time.

### 9. Preference-Conditioned Pareto HyperPrefix

- **One-sentence summary**: Generate a small prefix residual from explicit AWT and spillback budgets so one frozen VLM represents a controllable family of Pareto-efficient traffic policies.
- **Core hypothesis**: No fixed queue/wait scalarization is uniformly best across traffic regimes, but the four-action counterfactual table contains enough information to train a conditional policy that moves along the Pareto frontier at deployment.
- **Minimum viable experiment**: Add a two- or three-dimensional preference input such as `(AWT budget, spillback budget, queue priority)` to a tiny hypernetwork that generates 2-4 prefix residual tokens. Train by randomly sampling feasible budgets and choosing the best feasible action from stored raw candidate metrics. Compare one conditional model against three separately trained fixed-weight policies on constraint satisfaction, Pareto hypervolume, and online regret at both seen and interpolated budgets.
- **Bidirectional value**: Success turns the Queue-Wait contradiction into controllable behavior; failure shows that the available state representation or action space cannot support preference control, which is itself important for the system's scope.
- **Contribution type**: New method.
- **Risk level**: MEDIUM. Sparse four-action fronts may provide weak gradients for some budgets.
- **Estimated effort**: 2-3 weeks; 4-8 GPU-hours using existing counterfactual data.

### 10. Movement-Equivariant Graph HyperPrefix

- **One-sentence summary**: Encode the road network as a movement-level graph and use a shared hypernetwork to generate per-intersection prefix-token residuals for unseen topologies.
- **Core hypothesis**: Topology transfer requires relational movement connectivity and phase compatibility, not a learned embedding lookup over grid coordinates and network identity.
- **Minimum viable experiment**: Build movement nodes with capacity, turn type, phase compatibility, upstream/downstream adjacency, and congestion summaries already available from roadnet/state data. A 2-layer message-passing encoder feeds a hypernetwork that emits prefix deltas while Qwen3-VL stays frozen. Evaluate leave-one-topology-out transfer over Jinan, Hangzhou, New York or controlled topology mutations, and include an intersection-ID permutation test. Compare against no topology, the current MLP, and a graph encoder that only concatenates a pooled vector.
- **Bidirectional value**: A gain with ID-permutation robustness identifies topology as the bottleneck; no gain indicates that demand/label distribution, not graph representation, limits transfer.
- **Contribution type**: New method and structural diagnostic.
- **Risk level**: MEDIUM-HIGH. A credible leave-one-topology-out study needs at least three sufficiently distinct training/evaluation topologies.
- **Estimated effort**: 3-5 weeks; approximately 8-20 GPU-hours across two 5090s, plus counterfactual labels for topology tasks.

### 11. Uncertainty-Calibrated SimExpert Surrogate

- **One-sentence summary**: Train a lightweight graph-conditioned model to predict all four actions' metric distributions, and fall back to exact SimExpert whenever calibrated intervals cannot separate the candidates.
- **Core hypothesis**: Most states have easy, large-margin action rankings that a small surrogate can predict, while exact simulation is needed only for OOD or overlapping-cost states.
- **Minimum viable experiment**: Train on existing full counterfactual records to predict per-action ATT/AQL/AWT/spillback and uncertainty from frozen PhaseVLM embeddings plus topology. Use flow-disjoint conformal calibration. On a held-out network or demand shift, accept a surrogate winner only when its upper confidence bound beats every competitor's lower bound; otherwise query SimExpert. Report exact-query rate, top-action regret, constraint violations, calibration coverage, and speedup.
- **Bidirectional value**: Good calibrated transfer makes active and online Stage 3 feasible; poor OOD calibration establishes that counterfactual dynamics, not label volume, are the irreducible bottleneck.
- **Contribution type**: New method and systems result.
- **Risk level**: HIGH. A surrogate may interpolate within one network but fail under the topology shifts Stage 3 is meant to solve.
- **Estimated effort**: 3-5 weeks; 4-12 GPU-hours for the surrogate, with data collection likely dominating total time.

## First Three Pilot Proposals

No pilots were launched. Project rules require the complete command and explicit user approval before any experiment starts.

| Pilot | Minimal scope | Pre-registered decision rule | Estimated cost |
|---|---|---|---|
| Idea 1: Horizon stability | 32 network snapshots, four actions, four horizons | Continue to temporal-robust training if more than 20% of states flip winner or the 30-second winner has more than 10% normalized regret at 120 seconds | Simulator only for audit; optional <1 GPU-hour |
| Idea 2: Joint interactions | 24 snapshots, one congested adjacent pair, 16 joint actions | Continue if independent winners disagree with the pair oracle in more than 15% of cases and incur more than 5% normalized pair cost | Simulator only for audit; optional 1-3 GPU-hours |
| Idea 3: Active querying | One seed, `K=32`, regret acquisition versus random and entropy | Continue if regret-aware acquisition reduces held-out counterfactual regret by at least 15% without worsening AWT | About 2-3 GPU-hours plus equal SimExpert budgets |

The percentage thresholds are pilot go/no-go criteria, not paper-level significance claims. Full experiments still require paired simulator seeds and multi-seed uncertainty intervals.

## Eliminated or Merged Directions

| Direction | Reason eliminated or merged |
|---|---|
| Vanilla DPO on winner/loser pairs | Too close to "apply DPO to TSC" and discards the four-action metric table; replaced by Idea 7's margin-aware, reference-anchored listwise test. |
| Replace the topology MLP with a generic GNN | Insufficient novelty and vulnerable to ID memorization; upgraded to movement equivariance, prefix generation, and leave-one-topology-out tests in Idea 10. |
| More fixed queue/wait weight sweeps | The likely answer is configuration-specific and does not resolve the conceptual trade-off; replaced by explicit budgets and a conditional Pareto policy in Idea 9. |
| Entropy-minimization test-time adaptation | Unsafe because confident traffic-control errors provide no self-supervised correction signal; replaced by counterfactual risk gating in Idea 8. |
| Larger random `K` for hard BC | Already exposes the episode cap and label-efficiency problem without adding a mechanism; Ideas 3 and 4 change query allocation and timing under the same budget. |

## Suggested Execution Order

1. **Validate the expert before optimizing the student**: run Ideas 1 and 2, then Idea 6 if deterministic-future fragility remains plausible.
2. **Audit representation invariance**: run Idea 5 in parallel with the simulator diagnostics because it needs no new labels.
3. **Improve label efficiency under a fixed budget**: compare Ideas 3 and 4 using the same snapshot pool and source checkpoint.
4. **Settle the loss-function claim cleanly**: run Idea 7 only after full candidate-metric coverage is verified.
5. **Choose the paper's main extension from evidence**: pursue Idea 9 for multi-objective failures, Idea 10 for topology failures, or Idea 8 for concentrated deployment failures.
6. **Build the surrogate last**: Idea 11 is valuable only after the exact SimExpert target and failure regimes are understood.

## Overall Recommendation

The strongest paper path is not to begin with the largest architecture. Start with the **expert-validity triad**: horizon stability, neighbor-action interaction, and future-arrival robustness. These experiments can reveal that the current counterfactual labels are biased, or provide unusually strong validation that they are trustworthy. Either answer materially changes how simulator-supervised traffic control should be designed.

If the expert survives those tests, the best moderate-compute Stage 3 is **regret-aware active querying plus budget-neutral Counterfactual DAgger**, trained with a **reference-anchored listwise objective**. This combination directly addresses the current random-query, one-shot, hard/soft-target limitations while preserving PhaseVLM's distinctive frozen-VLM and prefix-adaptation design. The graph hyperprefix and learned surrogate are higher-upside follow-ons, but they should not be the first bet without diagnostic evidence that topology or query cost is the actual bottleneck.
